# SecADR-025: Two-Stage Confidential Authentication Gate & Legal Aesthetic Decor Architecture

- **Status:** Approved & Enforced
- **Version:** 1.0 (Sprint S018 Hardening)
- **Domain:** Security Architecture, Identity & Access Management, Forensic Confidentiality, UI/UX Legal Styling
- **Standard:** B-SDD Methodology v1.3 · ISO/IEC 27037 · Art. 73 CPP Suisse · Art. 13 LLCA
- **Supersedes:** Legacy single-screen PIN entry, hardcoded PIN leaks (`0523`), direct administrator bypass buttons
- **Enforcement:** Invariant L-01, Invariant L-02, Invariant L-03, Invariant L-05, **Invariant L-06 (Confidentiality & Zero-Leakage Gate)**

---

## 1. Судовий та безпековий контекст (Context & Rationale)

Платформа **B-SDD Legal Advocate Cockpit** призначена для супроводу кримінальних проваджень у Швейцарії (зокрема досьє *Ministère public du canton de Vaud*, Dossier `PE24.014624-SBA`). 

Відповідно до **ст. 73 КПК Швейцарії (CPP)** та **ст. 13 Федерального закону про адвокатуру (LLCA)**, матеріали досудового слідства та адвокатська таємниця підлягають безумовному захисту від несанкціонованого доступу та розголошення.

### Виявлені дефекти попередніх версій:
1. **Витік конфіденційного коду:** Тексти інтерфейсу та плейсхолдери містили явне відображення PIN-коду `(0523)` усіма мовами (`uk`, `fr`, `de`, `it`, `en`).
2. **Прямі кнопки обходу (Bypass Buttons):** Наявність кнопок *"Увійти як Адміністратор (0523)"* та *"Швидкий допуск"* дозволяла авторизуватися в системі в обхід криптографічної перевірки особистості через Google Account.
3. **Змішування рівнів доступу:** Локальний PIN-код термінала хибно використовувався як суверенний ключ входу замість захисного шару фізичного термінала.

## 2. Інваріант L-06: Двоконтурний шлюз допуску (Two-Stage Gate)

Починаючи зі Спринту S018, встановлюється непорушний архітектурний інваріант **L-06**:

```
+-----------------------------------------------------------------------------------+
|                           КОНФІДЕНЦІЙНИЙ ШЛЮЗ (AUTHGATE)                           |
+-----------------------------------------------------------------------------------+
                                         |
                       [Чи увімкнено PIN-захист?]
                               /            \
                     ТАК /                НІ \
                         v                     v
+----------------------------------+  +----------------------------------+
| КОНТУР 1 (ОПЦІЙНИЙ): PIN-КОД     |  |                                  |
| - Додатковий рівень захисту від  |  |                                  |
|   сторонніх очей біля термінала  |  |                                  |
| - Введення PIN переводить на     |  |                                  |
|   Контур 2 (НІКОЛИ не входить    |  |                                  |
|   в систему напряму!)            |  |                                  |
+----------------------------------+  |                                  |
                 |                     |                                  |
                 +----------+----------+                                  |
                            |                                             |
                            v                                             v
+-----------------------------------------------------------------------------------+
| КОНТУР 2 (ОБОВ'ЯЗКОВИЙ): GOOGLE ACCOUNT IDENTITY GATE (Zero-Trust OAuth2)         |
| 1. Авторизація через захищений шлюз Google Account (Appwrite OAuth2 Session)      |
| 2. Криптографічна перевірка email за закритим білим списком (HARDENED_WHITELIST): |
|    - tukroschu@gmail.com    -> Super Admin (SBA Lead)                             |
|    - arsen.k111999@gmail.com -> Victime / Partie Plaignante (Art. 115/118 CPP)     |
|    - vokov.dev@gmail.com    -> SecOps Administrator                               |
|    - counsel.vaud.vd@...    -> Avocat / Legal Counsel                             |
| 3. Якщо email є в списку -> Допуск із відповідною процесуальною роллю             |
| 4. Якщо email відсутній  -> Жорстке блокування доступу (Art. 73 CPP / 320 CP)     |
+-----------------------------------------------------------------------------------+
```

### Суворі правила інваріанта L-06:
1. **Zero Information Leakage:** Жодних згадок PIN-коду, чисел `0523`, підказок або паролів у відкритому вигляді в коді, плейсхолдерах чи локалізаціях.
2. **Zero Direct Bypass:** Повне видалення функції `handleDirectAdminLogin` та будь-яких кнопок прямого входу без проходження верифікації Google-акаунта.
3. **Role-Based Whitelist Isolation:** Усі права (перегляд доказів, верифікація WORM, редагування акторів, експорт Kindle/PDF) прив'язані виключно до перевіреного email Google-сесії.
4. **Адміністративне керування:** Опція захисту PIN-кодом (`isPinProtectionEnabled`) налаштовується виключно адміністратором у меню налаштувань (`SettingsModal` -> вкладка «Безпека»).

## 3. Архітектура візуального оформлення та юридичного декору (Legal Decor Framework)

Сторінка авторизації формує перше офіційне враження для швейцарських судових інстанцій, прокурорів (*Procureur général*), адвокатів (*Ordre des Avocats Vaudois*) та міжнародних експертів.

### 3.1. Кольорова палітра та естетика
- **Фон (Canvas):** Глибокий інституційний нічний ультрамарин (`#070B14`, `#080C14`, `#0B1120`).
- **Контейнери (Glassmorphic Vault):** Напівпрозорі панелі з розмиттям `backdrop-blur-xl`, тонким бордером `border-slate-800` або `border-blue-900/50` та м'яким внутрішнім світінням `shadow-2xl`.
- **Акценти юстиції:**
  - Тепле золото / амбер (`#F59E0B`, `#D97706`): символ швейцарської правової традиції, шальки терезів, печатки.
  - Федеральний синій (`#2563EB`, `#1D4ED8`): інституційні кнопки дій Google OAuth та підтвердження.
  - Смарагдовий (`#10B981`): верифікація WORM-ланцюжка та відповідність ISO/IEC 27037.
  - Рубіновий (`#EF4444`, `#991B1B`): процесуальне блокування доступу за Art. 73 CPP.

### 3.2. Композиційні зони для розміщення юридичного декору
Сторінка входу розбита на 4 архітектурні декоративні шари:

1. **Фоновий декор (Backdrop Legal Watermarks & Guilloche):**
   - Тонкі геометричні лінії гільйошу (гравюра судових бланків Конфедерації).
   - Латинські юридичні максими у вигляді ледь помітних напівпрозорих написів (font-serif, opacity 5-10%):
     - *«Iustitia est constans et perpetua voluntas ius suum cuique tribuendi»* (Ульпіан).
     - *«Nulla poena sine lege, nullum crimen sine iniuria»*.
     - *«Audiatur et altera pars»*.
   - Текстура швейцарського гербового паперу з водяними знаками.

2. **Інституційний герб та заголовок (Heraldic Brand Header):**
   - Градієнтна іконка щита та терезів юстиції (`Scale`, `ShieldCheck`).
   - Бейдж судової юрисдикції: `Swiss LegalTech · B-SDD Framework · Canton de Vaud`.
   - Процесуальний заголовок: `PE24.014624-SBA · Ministère public du canton de Vaud`.

3. **Службовий правовий меморандум (Judicial Memorandum Box):**
   - Юридичне застереження про таємницю слідства (Art. 73 CPP, Art. 13 LLCA).
   - Кнопка відкриття партнерського та договірного меморандуму (`btn_legal_memo`).
   - Процесуальні посилання на статті швейцарських кодексів (CPP Art. 73, Art. 115, LAVI Art. 13).

4. **Футер судово-технічних гарантій (Forensic Ledger Footer):**
   - Стандарт криптографічної цілісності: `B-SDD Protocol v3.0 · ISO/IEC 27037 WORM Ledger`.
   - Посилання на захист прав потерпілих: `LAVI Reference & Ordre des Avocats Vaudois`.

### 3.3. Правила реалізації декоративних елементів:
- **WCAG AAA контрастність:** Декоративні елементи не повинні заважати читанню тексту та взаємодії з елементами форми.
- **Незмінність форми введення:** Декорування сторінки не повинно модифікувати логіку `handlePinSubmit`, `handleExecuteGoogleAuth` та стан валідації.
- **Адаптивність (Mobile & Desktop):** На мобільних екранах фонові водяні знаки та складний гільйош автоматично приховуються (`hidden sm:block`) для збереження продуктивності та компактності клавіатури.
- **Підтримка E-Ink режиму:** У разі увімкнення режиму електронного чорнила (E-Ink Mode) кольорові градієнти замінюються на строгі висококонтрастні чорно-білі штрихи без напівпрозорості.
