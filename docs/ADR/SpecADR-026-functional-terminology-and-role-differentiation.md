# SpecADR-026: Functional Legal Terminology & Role-Differentiated User Interface Architecture

- **Status:** Approved & Enforced
- **Version:** 1.0 (Sprint S018 Hardening)
- **Domain:** Human-Computer Interaction, Swiss Legal Taxonomy, Role-Based Persona Differentiation (RBAC), UI/UX Cleanliness
- **Standard:** B-SDD Methodology v1.3 · Swiss Criminal Procedure Code (CPP) · Federal Bar Standards (FSA/OAV)
- **Supersedes:** Monolithic developer-centric UI, database jargon leakage ("Utopia DB :251", "KùzuDB", "WORM atomic supersession", ports, nodes)
- **Enforcement:** Invariant L-01, Invariant L-02, Invariant L-03, Invariant L-04, Invariant L-05, Invariant L-06

---

## 1. Контекст та Проблематика (Context & Problem Statement)

Платформа **B-SDD Legal Advocate Cockpit** одночасно обслуговує дві принципово різні категорії користувачів:
1. **Професійні швейцарські адвокати та слідчі органи (Advocate Persona):**
   Потребують суворої юридичної точності, кваліфікації за КПК (CPP), посилань на прецеденти Федерального суду (ATF 146 IV 9), засобів процесуального доказування (Art. 139, 141 CPP), офіційного експорту судових реєстрів (Bordereau PDF/A) та десків верифікації первинних доказів (HITL Evidence Desk).
2. **Потерпіла сторона, довірителі та звичайні громадяни (Client/Victim Persona):**
   Потребують простого, заспокійливого та зрозумілого інтерфейсу без перевантаження технічним або вузькопроцесуальним жаргоном. Мета — надати прозорий огляд стану справи, переліку матеріалів, учасників та можливість зручної консультації зі штучним інтелектом.

### Виявлені дефекти інтерфейсу:
- **Засмічення технічним жаргоном:** В інтерфейсі користувача використовувалися терміни розробників: *"Utopia DB :251"*, *"Вузол .234"*, *"MemPalace KùzuDB"*, *"Port :8766"*, *"Port :8162"*, *"WORM Bitemporal Ledger"*, *"Google Cloud Run Identity Gateway"*, *"cloudflared"*.
- **Відсутність диференціації ролей:** Клієнти з роллю `user` бачили той самий складний інженерно-процесуальний пульт керування з кнопками компіляції WORM, перевірки черги HITL, технічних інструментів та перемикання демо-кейсів ("Холмс").

Цим рішенням встановлюється заборона на використання сирих назв баз даних та серверних компонентів у призначених для користувача текстах:

| `MemPalace KùzuDB` | **База правових зв'язків справи** / *Graphe relationnel* | **Матеріали та факти** / *Éléments du dossier* |
| `WORM Bitemporal Ledger` | **Реєстр незмінності судових доказів** / *Registre officiel d'intégrité probatoire* | **Офіційні матеріали справи** / *Pièces officielles* |
| `Scellé dans WORM` | **Офіційно засвідчено в реєстрі** / *Certifié au dossier* | **Перевірено адвокатом** / *Validé par le conseil* |

| `Локальний шлях на вузлі .234` | **Джерело матеріалу** / *Source d'archive* | **Файл документа** / *Fichier* |

## 3. Архітектура диференціації інтерфейсу (Role-Differentiated Persona Architecture)

Система автоматично адаптує навігацію та робочий простір залежно від авторизованої ролі користувача (`AuthorizedUser.role`):

```
                                  [Авторизація через AuthGate]
                                                |
                            +-------------------+-------------------+
                            |                                       |
                   [role: user / viewer]             [role: lawyer / admin / super_admin]
                            |                                       |
                            v                                       v
               +--------------------------+            +--------------------------+
               |      CLIENT PERSONA      |            |     ADVOCATE PERSONA     |
               +--------------------------+            +--------------------------+
               | 1. 📁 Матеріали та докази|            | 1. 🌿 Процедури (5)      |
               | 2. 👥 Учасники справи    |            | 2. 🧰 Інструменти        |
               | 3. 📅 Хронологія подій   |            | 3. 🤖 ШІ-Студія          |
               | 4. 💬 Консультація / ШІ  |            | 4. ⚖️ Черга HITL         |
               +--------------------------+            +--------------------------+
               | Особливості:             |            | Особливості:             |
               | - Стартова вкладка:      |            | - Стартова вкладка:      |
               |   `factbook`             |            |   `procedures`           |
               | - Приховано HITL-чергу   |            | - Повний доступ до       |
               | - Приховано WORM-леджер  |            |   судового бандлу (PDF/A)|
               | - Приховано демо-кейси   |            | - Доступ до налаштувань  |
               | - Приховано бандл PDF/A  |            |   та бітемпорального     |
               |   та технічні тунелі     |            |   WORM-засвідчення       |
               +--------------------------+            +--------------------------+
```

### 3.1. Клієнтський режим (Client Persona — `user`, `viewer`)
- **Навігаційні вкладки:**
  1. `client_tab_evidence`: **📁 Матеріали та докази** (`factbook`) — перегляд документів, фотографій та медичних висновків.
  2. `client_tab_actors`: **👥 Учасники справи** (`actors`) — перелік учасників процесу та їхні ролі.
  3. `client_tab_timeline`: **📅 Хронологія подій** (`procedures`) — зрозумілий таймлайн ключових дат та подій.
  4. `client_tab_copilot`: **💬 Консультація / ШІ** (`ai_copilot`) — спокійний діалог з роз'ясненнями матеріалів справи.
- **Обмеження:** Повне приховування черги модерації доказів Spark, вилучення кнопок експорту судового бандлу та системних перемикачів демо-режиму ("Холмс").

### 3.2. Адвокатський режим (Advocate Persona — `lawyer`, `admin`, `super_admin`)
- Зберігає повний доступ до всіх спеціалізованих інструментів:
  * Процедурний маршрут КПК (5 стадій).
  * Каталог інструментів досьє (Factbook, фігуранти, арешт активів, реєстр незмінності).
  * ШІ-Юрисконсульт із практикою Федерального суду (ATF 146 IV 9, ст. 318 КПК).
  * Черга форензік-інспекції кандидатів Spark L1 (HITL Verification Desk).
  * Швидке перемикання між ізольованим демо-кейсом Холмса та суверенним судовим досьє SBA.

## 4. Верифікація та відповідність стандартам (Compliance)

1. **Багатомовність (i18n):**
   Усі клієнтські ключі впроваджено в `UI_TRANSLATIONS` для всіх 5 мов (`uk`, `fr`, `de`, `it`, `en`).
2. **Стандарт криміналістики ISO/IEC 27037:**
   Всі описи цифрових відбитків SHA-256 зберігають юридичну та технічну строгість без використання сирого сленгу.
3. **Захист таємниці слідства (Art. 73 CPP):**
   Клієнти не мають доступу до адміністративних журналів і технічних тунелів, що мінімізує вектор випадкового витоку інформації.
